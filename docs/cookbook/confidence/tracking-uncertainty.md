# Recipe: Tracking Uncertainty with @confidence and @uncertain

## Problem

You're writing code but aren't 100% sure it handles all cases correctly. How do you communicate this uncertainty to future maintainers (human or AI)?

## Solution

Use `@confidence` and `@uncertain` annotations to make uncertainty explicit:

```agentic
@confidence(0.75)
@uncertain("Edge case: multiple date formats possible, only ISO tested")
@partial("Handles ISO 8601, other formats untested")
func parseDate(input: string) -> Result<Date, ParseError> {
  // Only tested with ISO 8601 format
  if isISO8601(input) {
    return Ok(Date.parse(input))
  }

  @uncertain("US format (MM/DD/YYYY) parsing is best-effort")
  if looksLikeUSFormat(input) {
    return tryParseUS(input)
  }

  return Err(ParseError.UNSUPPORTED_FORMAT)
}
```

## Discussion

### When to Use Low Confidence

Use confidence < 0.80 when:
1. **Complex logic** - Algorithm has many branches
2. **Edge cases unknown** - Haven't tested all scenarios
3. **External dependencies** - Relies on uncertain APIs
4. **New code** - Recently written, needs validation
5. **AI-generated** - Code generated by LLM needs review

### Confidence Level Guide

| Range | Meaning | Action |
|-------|---------|--------|
| 0.95-1.00 | Very confident | Production-ready, well-tested |
| 0.85-0.95 | Good | Minor edge cases, safe for use |
| 0.70-0.85 | Moderate | Known limitations, documented |
| 0.50-0.70 | Low | Experimental, needs review |
| 0.00-0.50 | Very low | Prototype only, significant work needed |

### Using @uncertain for Explanation

Always explain WHY you're uncertain:

```agentic
// ❌ Not helpful
@confidence(0.60)
@uncertain("Not sure about this")

// ✓ Helpful
@confidence(0.60)
@uncertain("Regex pattern may not handle all email formats. Tested: Gmail, Outlook. Untested: International domains, plus-addressing")
```

## Examples

### Example 1: API Integration

```agentic
@confidence(0.70)
@uncertain("Third-party API response format may change without notice")
@needs(http: HttpClient, logger: Logger)
func fetchWeather(city: string) -> Result<WeatherData, ApiError> {
  response = http.get("https://api.weather.com/v1/current/${city}")

  @uncertain("API may return non-standard error codes")
  if response.status != 200 {
    logger.warn("Unexpected status: ${response.status}")
    return Err(ApiError.UNEXPECTED_STATUS(response.status))
  }

  weather = response.json<WeatherData>() match {
    Ok(data) -> data,
    Err(e) -> {
      @uncertain("JSON schema validation not implemented")
      return Err(ApiError.PARSE_ERROR(e))
    }
  }

  return Ok(weather)
}
```

### Example 2: Algorithm Implementation

```agentic
@confidence(0.82)
@uncertain("Algorithm complexity not verified for large inputs (n > 10000)")
@partial("Works for typical inputs, performance unknown for edge cases")
func quickSort(arr: number[]) -> number[] {
  if arr.length <= 1 {
    return arr
  }

  pivot = arr[0]
  left = arr.filter(x => x < pivot)
  right = arr.filter(x => x >= pivot)

  return quickSort(left) + [pivot] + quickSort(right)
}
```

### Example 3: Increasing Confidence

```agentic
// Version 1: Initial implementation
@confidence(0.60)
@stub("Basic structure only")
func validatePassword(password: string) -> Result<void, ValidationError>

// Version 2: Add basic checks
@confidence(0.75)
@partial("Checks length and basic requirements")
@uncertain("No dictionary attack prevention")
func validatePassword(password: string) -> Result<void, ValidationError> {
  if password.length < 8 {
    return Err(ValidationError.TOO_SHORT)
  }
  if !hasNumber(password) {
    return Err(ValidationError.NO_NUMBER)
  }
  return Ok(void)
}

// Version 3: Complete implementation
@confidence(0.92)
@complete
@property("rejects short passwords")
@property("requires mixed case")
@property("requires special characters")
func validatePassword(password: string) -> Result<void, ValidationError> {
  checks = [
    (password.length >= 8, ValidationError.TOO_SHORT),
    (hasLowerCase(password), ValidationError.NO_LOWERCASE),
    (hasUpperCase(password), ValidationError.NO_UPPERCASE),
    (hasNumber(password), ValidationError.NO_NUMBER),
    (hasSpecialChar(password), ValidationError.NO_SPECIAL_CHAR),
    (!isCommonPassword(password), ValidationError.TOO_COMMON)
  ]

  for (check, error) in checks {
    if !check {
      return Err(error)
    }
  }

  return Ok(void)
}
```

## Monitoring Confidence in Production

Track actual success rates and compare to claimed confidence:

```agentic
@confidence(0.85)
@monitor_runtime(samples: 1000)
func risky_operation(input: Data) -> Result<Output, Error> {
  // Runtime monitoring tracks:
  // - Actual success rate
  // - Statistical confidence interval
  // - Alerts if claimed confidence is outside interval
}
```

Runtime reports:

```
Function: risky_operation
  Claimed confidence: 0.85
  Actual success rate: 0.87 (n=1000)
  95% confidence interval: [0.84, 0.89]
  Status: ✓ VALID (claim within interval)
```

## Tips for AI Agents

When an AI agent writes code:

1. **Start conservative:** Begin with @confidence(0.70)
2. **Test thoroughly:** Add property tests, run 1000 cases
3. **Measure actual rate:** Use runtime monitoring
4. **Increase gradually:** Raise confidence as evidence accumulates
5. **Document uncertainty:** Always use @uncertain for known gaps
